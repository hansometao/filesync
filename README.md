# 文件夹同步备份工具

一个**图形化**的文件夹同步备份工具，支持两目录对比同步（单向镜像 / 双向同步可配置）、
内置常驻定时调度，以及安全的冲突处理与日志审计。

> 最低运行环境：**CPython 3.8.x**（兼容 Windows 7）。仅依赖标准库 + tkinter，
> 哈希可选 `xxhash` 加速（缺失自动回退 `hashlib`），**零强制第三方依赖**。

---

## 功能特性

- 两目录对比同步：递归扫描，区分**新增 / 修改 / 删除 / 冲突**四类差异
- 同步方向可配：**单向镜像**（源→目标）或 **双向同步**
- 对比依据：先比 `修改时间 + 大小`（快），不一致再算**内容哈希**确认（准）
- 定时调度：内置常驻调度器，支持
  - **间隔**：每隔 N 分钟 / 小时 / 天
  - **每日固定时刻**：可设多个（如 `08:00,20:00`）
  - **每周固定时刻**：可选周几 × 多个时刻（如 周一、三、五 的 `09:00,18:00`）
- 冲突处理：新版本胜出 / 源侧胜出 / 目标侧胜出 / 跳过 / 逐个询问（默认新版本胜出，
  且**先备份落败方**为 `文件名.conflict-<时间戳.毫秒>` 副本（同秒多冲突以序号区分），绝不静默丢数据；
  备份副本**只保留在落败方本地**，不会被后续同步传播到对端）
- 过滤规则：include / exclude glob（如 `*.tmp`、`__pycache__/`）；
  设置 include 后只同步匹配文件，空目录不再被传播（无 include 时照常同步空目录）
- 空目录同步：无 include 过滤时，目录条目纳入对比——单向镜像会创建（开启"删除目标多余文件"时也会清理）
  目标侧空目录，双向同步会合并两侧目录；文件与目录同名（类型冲突）明确报失败，不会静默或无限重试
- 差异预览：执行前 dry-run 列出将执行动作，危险操作（删除/覆盖）二次确认；
  **所见即所得**——确认后直接按预览结果执行（基于预览时的快照），不再重新扫描；
  上千条动作的差异列表支持滚动查看
- 进度与取消：扫描/执行期间显示当前处理文件与进度动画，随时可点**取消**中断（已完成的动作保留）
- 日志审计：每次运行记录动作明细，GUI 可查看，文件留存于 `logs/`（超过 2MB 自动轮转，保留最近 1 份历史）
- 调度兜底：停机期间错过的周期在下次启动时**补跑一次**；到点时任务恰在运行则**自动顺延 60 秒**重试，
  绝不静默丢弃；补跑/触发后下次周期从**触发时刻**重新起算，不会因旧锚点造成连续重复触发

## 安装与运行

### Windows 7 用户（重要）
1. 从 python.org 下载并安装 **Python 3.8.x**（例如 `python-3.8.10-amd64.exe`），
   **务必勾选 "Add Python 3.8 to PATH"**。
2. 解压本工具到任意目录（路径建议不含中文/空格，或确保不长于 260 字符；
   工具已对长路径做 `\\?\` 兼容）。
3. 双击 `main.py`，或在目录内打开命令行执行：
   ```
   python main.py
   ```
4. （可选加速）`pip install xxhash`

> Windows 7 的最后官方支持的 CPython 版本为 3.8.x，请勿使用 3.9+ 解释器。

### Linux / macOS
```
python3 main.py
# 可选：pip install xxhash
```

### 命令行无头模式（配合任务计划程序 / cron 无人值守）
```
python main.py --list            # 列出全部任务（ID / 名称 / 启用状态 / 方向）
python main.py --sync <名称或ID>  # 立即执行一次指定任务
python main.py --help            # 显示帮助
```
- `--sync` 退出码：`0` 成功；`1` 任务未找到或已禁用；`2` 部分文件失败（摘要中含失败数）；`3` 同步过程异常（业务错误已捕获并落盘为"失败"状态）。
- 任务请先用 GUI 创建，`--sync` 按名称或 ID 匹配（ID 可用 `--list` 查看）。
- 无参数启动则进入图形界面。

## 打包为独立 exe（可选）

本工具可打包成**单文件、无控制台（windowed）**的可执行文件，双击即启动 GUI。

### 打包相关文件
- `build_exe.py`：一键打包脚本（跨平台）
- `folder_sync.spec`：PyInstaller 打包配置（单文件 + 无控制台 + 图标）
- `make_icon.py`：生成占位图标 `app.ico`（可替换为你的正式图标）

### 在 Windows 上生成 exe
1. 在 **Windows 7 / Python 3.8.x** 环境安装打包工具：
   ```
   pip install "pyinstaller==5.13.2"
   ```
   > PyInstaller 官方仅保证 Windows 8+，Win7 为 best-effort；建议用 5.x 系列以获得更好兼容。
2. （可选）为加速哈希可先 `pip install xxhash`。
3. 运行：
   ```
   python build_exe.py
   ```
4. 产物在 `dist/folder_sync.exe`（单文件，约 7~10 MB）。

### 打包后的行为
- **GUI**：双击 `folder_sync.exe` 直接进入图形界面，无黑色控制台窗口。
- **CLI**：`folder_sync.exe --list` / `--sync <名称或ID>` / `--help` 仍可用；
  windowed 打包下无控制台，结果以**弹窗**显示。无人值守管道/重定向请改用
  `python main.py`，或重新打包为 console 版（spec 里 `console=True`）。
- **数据落点**：`config/` 与 `logs/` 生成在 **exe 同目录**（不会写到临时目录）。

### 单文件 vs 目录版
- 单文件（默认）：分发方便，但首次启动需解压、略慢，个别杀软可能误报。
- 目录版：启动快、更稳。如需目录版，可执行 `pyinstaller --onedir --windowed main.py`
  或把 spec 改为 COLLECT 结构。

### 关于本仓库的 Linux 验证
- 本仓库在 Linux 环境跑过一次打包验证，产出 `dist/folder_sync`（Linux 可执行文件），
  用于验证 spec / 入口 / frozen 路径 / 依赖收集正确；该 Linux 产物**仅供验证**，
  不能替代 Windows exe。
- Linux 系统 Python 未安装 tkinter，因此 Linux 打包产物中的 GUI 无法启动验证；
  GUI 功能已通过源码层 Xvfb 冒烟测试覆盖，Windows 端打包后（Python 3.8 自带
  tkinter，PyInstaller 自动收集）GUI 会正常。

## 使用说明

1. 点击 **新增任务**，填写：
  - 任务名称（**需唯一**，与已有任务重名会被拦截）、源目录、目标目录（可点"浏览"选择）
  - 同步方向：单向镜像 / 双向同步
  - 任务总开关「启用任务」：取消勾选可暂停该任务（不参与定时，**也不允许手动同步**，点"立即同步"会收到提示）
  - 单向镜像可勾选"删除目标多余文件"（严格镜像）；双向可勾选"传播删除"
   - 定时：勾选"启用"，选间隔 / 每日时刻 / 每周时刻，填参数
   - 包含/排除规则、冲突策略
2. 选中任务后点 **立即同步**：先弹出差异预览（大目录扫描期间显示进度、可取消），
   确认后**按预览结果执行**（所见即所得）；执行期间同样显示进度并支持取消
3. 工具栏 **启动调度**：开启后台常驻调度，按各任务计划自动同步
4. 删除/编辑：选中任务后点对应按钮；任务**运行中时编辑/删除会被拒绝**（防并发写坏配置），
   请等待完成或取消后再操作
5. 底部日志面板实时显示运行记录
6. 关闭窗口时若有任务正在运行，会**有界等待（最多 5 秒）**其结束后再干净退出

### 配置文件
- 任务配置持久化在 `config/tasks.json`，可手动备份；
- 双向同步的上次快照（baseline）单独存放在 `config/baseline/<任务ID>.json`——
  旧版本内嵌在 tasks.json 中的 baseline 会在启动时**自动迁移**为独立文件；
- 损坏的 tasks.json 不会被覆盖，而是自动备份为 `tasks.json.corrupt-<时间戳>` 后从空配置启动，
  便于手工找回。

## 兼容性说明（Windows 7 专项）

- **长路径**：自动对深层路径加 `\\?\` 前缀，绕过 260 字符 `MAX_PATH` 限制。
- **FAT32 时间精度**：FAT 文件系统 mtime 精度仅 2 秒；工具在 size 相同、mtime 仅差
  容差时回退到内容哈希比较，避免误判；冲突"新版本"比较同样带 2 秒容差。
- **软链**：扫描**不跟随**符号链接（避免循环），也**不复制、不记录**链接本身（Win7 建链需管理员）；
  若需备份链接指向的内容，请直接选择其真实目录作为源/目标。
- **编码**：日志文件强制 UTF-8，路径用 `os.fsdecode/fsencode` 处理。
- 代码严格不使用 3.9+ 才引入的语法/标准库特性，确保 3.8 可运行。

## 已知限制与说明

- **符号链接**：默认完全忽略（不跟随、不复制、不记录）。如需同步链接目标内容，请把真实目录作为源/目标。
- **修改时间容差**：为兼容 FAT32（2 秒精度），`size` 相同且 `mtime` 差异在容差内会回退到内容哈希确认。
  在 NTFS（精度 100ns）上，若同一文件在 <2 秒内被快速连续修改，理论上可能被容差掩盖；双向同步已通过
  baseline 记录的内容哈希做兜底（`mtime` 微差时比对内容），最大限度避免漏同步。
- **双向同步首跑**：首次双向（无上次同步快照）会把两端文件相互合并，内容不同的同名文件按冲突策略处理；
  请确保两端确为同一数据集的镜像关系，或先用「立即同步」预览确认。
- **单向镜像**：默认仅镜像源到目标，目标多余文件**不删除**（仅记录）；需勾选"删除目标多余文件"才清理。
- **双向目录删除不传播**：双向同步会合并两侧新增目录（含空目录），但目录的删除不跨端传播；
  文件删除后残留的空目录由目标端自动清理。
- **预览与执行的时间差**：确认执行基于**预览时刻的快照**；若预览后外部程序又改动了目录内容，
  这些新改动不会反映在本次执行中（下次同步会正常检出）。预览与确认之间请尽量缩短间隔。
- **原子写临时文件**：复制采用"先写 `.tmp~` 临时文件再原子替换"，扫描时会跳过 `*.tmp~` 残留，
  中断不会留下半截文件。

## 自测

无界面核心逻辑测试（不需 GUI）：
```
python test_sync.py
```
覆盖：单向新增/修改/删除、双向合并、冲突解决（新版本/源侧/目标侧胜出 + 跳过 + 逐个询问的
异常/无效返回回退与无人值守回退 + 备份不传播）、调度器后台触发（interval 锚定自动补跑 +
运行中顺延 + 补跑后周期从触发时刻起算、daily/weekly 未到点不触发 + 停机补跑 + run_now
拒绝禁用任务）、非法每日时刻容错、损坏配置保留现场、并发保存完整性、FAT32 容差内微差检出、
include 过滤下空目录不传播、baseline 分离存储与旧格式自动迁移、部分失败状态上报、
数据安全回归（源目录不可达/扫描不完整时中止而非误删目标、skip 冲突不固化进 baseline）、
持久层字段清洗、任务名查重、logger 回调投递与超限轮转、
CLI 无头入口（--list / --sync 退出码 0/1/2/3 与异常状态落盘）。
